# Glossary — Composing Programs

**Abstraction barrier** — a boundary where each level of a program uses only the interface of the level below, never its representation (Ch 2.2)
**Call expression** — operator and operand subexpressions; evaluated by evaluating subexpressions, then applying operator's value to operands' values (Ch 1.2)
**Class attribute** — a value shared by all instances of a class, looked up when no instance attribute matches (Ch 2.5)
**Closure property** — the result of combination can itself be combined, enabling hierarchical structures like nested lists (Ch 2.3)
**Coercion** — converting one type to another so one operation covers mixed-type arguments (Ch 2.7)
**Constructor / selector** — functions that create a compound value and extract its parts; together they define a data abstraction (Ch 2.2)
**Currying** — transforming f(x, y) into g(x)(y); lets multi-argument functions work with single-argument HOF machinery (Ch 1.6)
**Data abstraction** — isolating how compound data is used from how it is represented (Ch 2.2)
**Decorator** — `@expr` syntax applying a higher-order function to a newly defined function (Ch 1.6)
**Dispatch dictionary** — a dictionary mapping message strings to functions; the mechanism beneath method lookup (Ch 2.4, 2.6)
**Environment** — a sequence of frames in which names are bound to values; gives expressions meaning (Ch 1.2–1.3)
**Environment diagram** — visualization of frames, bindings and function objects used to reason about evaluation (Ch 1.3)
**First-class** — status of values that can be named, passed, returned, and stored; functions are first-class in Python (Ch 1.6)
**Frame** — one binding table in an environment; a function call creates a new frame whose parent is the defining environment (Ch 1.3)
**Generator** — an iterator produced by calling a generator function (one containing `yield`); computes values lazily (Ch 4.2)
**Generic function** — a function that applies to arguments of multiple types, via shared interfaces, type dispatch or coercion (Ch 2.7)
**Higher-order function** — a function that takes functions as arguments or returns a function (Ch 1.6)
**Identity vs equality** — `is` tests same object; `==` tests equal contents; mutation makes the difference observable (Ch 2.4)
**Interface** — a shared set of messages (e.g. `__len__`, `__getitem__`) that lets different classes be used interchangeably (Ch 2.7)
**Iterator** — an object returning elements one at a time via `next`; maintains one-pass position state (Ch 4.2)
**Iterative improvement** — repeatedly apply `update` to a guess until `close(guess)` holds; general numerical pattern (Ch 1.6)
**Lexical scoping** — nested functions resolve names in the environment where they were *defined*, not called (Ch 1.6)
**Linked list** — pair of first element and rest-of-list (or empty); recursive sequence representation (Ch 2.3, 2.9)
**Memoization** — caching a pure function's results by argument to avoid recomputation (Ch 2.8)
**Message passing** — organizing behavior as responses to named messages sent to data values (Ch 2.4)
**Metalinguistic abstraction** — mastering complexity by defining a new language and building its interpreter (Ch 3.1, 3.4)
**Mutual recursion** — two functions defined in terms of each other; e.g. even/odd (Ch 1.7)
**Non-local assignment** — `nonlocal` rebinding a name in an enclosing frame, creating persistent local state (Ch 2.4)
**Order of growth** — how resource use scales with input size: Θ(1), Θ(log n), Θ(n), Θ(n²), Θ(bⁿ) (Ch 2.8)
**Pure function** — returns a value with no side effects; same args → same result (Ch 1.2)
**Read-eval-print loop (REPL)** — interpreter cycle: parse input, evaluate, print result, repeat; survives errors (Ch 3.4)
**Recursive leap of faith** — treating a recursive call as a correct functional abstraction while verifying only base case and combination (Ch 1.7)
**Special method** — double-underscore method (`__init__`, `__repr__`, `__add__`) invoked implicitly by the interpreter (Ch 2.7)
**Stream** — lazily computed linked list: first element explicit, rest computed on demand (Ch 4.2)
**Tail recursion** — recursive call in tail position; Scheme implements it in constant space (Ch 3.2)
**Tree** — value with a root label and a list of branches, each a tree; recursive data abstraction (Ch 2.3, 2.9)
**Tree recursion** — a function calling itself more than once per invocation; call structure forms a tree (Ch 1.7)
**Unification** — matching two expressions that both may contain variables; the engine of logic programming (Ch 4.5)
